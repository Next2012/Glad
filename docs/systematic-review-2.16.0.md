## 已实施的改进

| 问题 | 改进与验证 |
| --- | --- |
| 内部订阅积压后永久退出，影响群聊、通知和监督任务 | 保留有界队列及浏览器背压策略；核心消费者自动重新订阅、排空旧队列并从会话状态补全完成事件和待处理交互。通知和监督消费者在入队前过滤无关增量。补发问题事件保持 `question-request` 协议及监督来源，避免漏通知或误通知。 |
| 群聊每次 token 更新均读取成员文件 | 文件存储写入后增加版本号；按版本缓存会话到群聊的成员索引。加入、离开、恢复、删除后自动失效。回归验证 2,000 次流式事件只读取一次索引，离开后正确失效。 |
| 手机单聊草稿串会话、群聊草稿丢失 | 按会话保存文本、附件、技能和问答草稿；群聊保留文本、提及、引用和待发文件。上传回调绑定原附件数组及会话，切换后不转移附件归属。 |
| 桌面和手机尺寸切换重复连接、状态分裂 | 已有标签在窄屏继续复用；主文档视图迁入标签时关闭旧连接并移交草稿。窄屏提供返回列表入口。迁移清除群聊成员弹窗的旧返回路由。 |
| 后台标签持续渲染及轮询 | 抽出公共视图生命周期，后台仍接收事件并更新模型，延迟聊天 DOM 渲染；暂停定时、速度、子代理及群聊面板的后台展示轮询，激活后刷新。 |
| History/Git 被误认为正在阅读聊天 | 标签选择与本地子视图同时参与可见性判断。History 中完成的任务保持未读；返回聊天才确认。隐藏容器不覆盖聊天滚动锚点，侧栏尺寸变化保留阅读位置。 |
| 重连时历史分页缺口或旧请求错拼 | 同 epoch 且历史连续时保留已加载页；长时间断线造成窗口不连续时采用新尾页及其游标，并使旧分页与正文请求失效，保证缺失部分仍可向前加载。 |
| 快速切群聊时旧请求覆盖新页面 | 引入打开代际和归属检查；旧错误、旧成员弹窗回调不修改其他群聊。Git/History 读取也增加请求归属检查，刷新跟随当前 Git 子视图。 |
| 问答和标签清理卡死 | Claude 问答返回相关联的成功/失败结果，失败和断线保留答案并允许重试；UUID 缺失和 socket 发送异常均可恢复。标签卸载立即关闭连接，并对附件清理设置总时限。上传批次计数覆盖排队窗口，移交后进度通知新视图。 |
| 桌面卡片及批量附件可读性差 | 标题独占一行，路径与操作分区，次要顶栏按钮降低视觉权重；输入框继承字体并统一焦点态；附件换行、限高滚动、显示总数，文件名与移除按钮不再挤压。 |
| 手机触控及亮暗主题细节 | 增大附件和导航触控区域，修正问答焦点框裁切；定时标签置于输入区域内，避免遮挡对话；群聊气泡与引用使用主题色。 |

## 原生历史部署门禁发现

首次重启验收发现 Codex 历史从 10 条变为 8 条，部署脚本因此回退；用户消息和最终答案仍在，缺少中间说明及命令执行记录。经 OpenAI Docs 官方文档与本机协议 schema 核实，`itemsView: "summary"` 仅提供展示摘要。此轮增加只读原生 `event_msg/item_completed` 补全，限定 API 已返回的 turn、校验原生 thread 归属，单行 8 MiB、累计保留 32 MiB，跳过过大记录并支持取消。保留原有摘要分页，不请求完整大轮次 RPC。

补全合并按 API 顺序与 item ID 去重，覆盖并发命令完成顺序反转；不会带回已经撤回的其他轮次。已通过原始数据的只读复现核验，10 条原记录全部恢复。原生记录及备份仅保存在受限的临时部署目录，没有进入 Git。

参考：[OpenAI 官方 Codex App Server 文档](https://learn.chatgpt.com/docs/app-server)。
